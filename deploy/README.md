# Подключение GitHub к существующему Kourage на Timeweb

Подготовлено обновление вручную: вкладка Actions → «Обновить сайт на Timeweb» → Run workflow → основная ветка репозитория. Пока реквизиты и ключ не добавлены, соединение не настроено и запуск закончится сообщением о недостающей настройке.

## Однократная настройка

1. Загрузите только код в корень репозитория. Репозиторий может быть публичным; база, вложения и ключи в него не входят. Папки `.github`, `deploy`, `public_html` должны находиться в корне, без дополнительной внешней папки. На Mac скрытые файлы показывает сочетание Cmd+Shift+точка.
2. Убедитесь, что в Timeweb включён SSH-доступ. На главной странице в блоке доступа по FTP найдите адрес сервера. Логин — основной пользователь аккаунта; на показанном ранее аккаунте это co916506. Пароль в репозиторий не добавляйте.
3. Создайте отдельную пару SSH-ключей для GitHub Actions. Публичную часть добавьте в authorized_keys пользователя Timeweb, приватную — только в GitHub Secret TIMEWEB_SSH_KEY. Не используйте ключ от другого сервиса. Ключ предоставляет доступ к аккаунту хостинга: добавляйте его только после проверки, что это ваш репозиторий и правильный сервер. Инструкции для конкретного подключения нужно завершить после получения адреса сервера.
4. Получите публичный ключ SSH-сервера и сверяйте его отпечаток по доверенному источнику — например, через уже открытую веб-консоль Timeweb или поддержку. Запись known_hosts для точного адреса сервера сохраните в TIMEWEB_KNOWN_HOSTS. Сценарий намеренно не принимает неизвестный ключ автоматически.
5. В GitHub откройте **Settings → Secrets and variables → Actions**. На вкладке **Variables** добавьте TIMEWEB_HOST (адрес сервера без ssh://, без имени пользователя и без пути) и TIMEWEB_USER (логин). На вкладке **Secrets** добавьте TIMEWEB_SSH_KEY и TIMEWEB_KNOWN_HOSTS.
6. Для видеозвонков создайте API-ключ в панели Daily и добавьте его там же как Secret с именем DAILY_API_KEY. Ключ не попадает в репозиторий или public_html: при публикации он записывается в `courage/private/daily-api-key.txt` с закрытыми правами. Без этого секрета остальные разделы работают, а страница звонков показывает настройку подключения.
7. При необходимости включите Actions для репозитория. Запускайте обновление только из основной ветки. Первая загрузка должна выполняться после свежей резервной копии на Timeweb.

## Что обновляется

Список публичных файлов фиксирован в `deploy/public-files.txt`. Назначение — существующий **courage/public_html**. `.htaccess` входит в управляемый список, чтобы политики безопасности соответствовали онлайн-редактору и встроенному звонку; `.user.ini` не перезаписывается.

Папка private не передаётся и не очищается. Серверный код может выполнить предусмотренную миграцию при следующем запросе к сайту, как и после ручного обновления. Поэтому история кода не заменяет резервную копию данных.

Предыдущие версии изменённых файлов складываются в **courage/.code-backups/номер-запуска-попытка** вне публичной папки. В этой копии только изменённые файлы программы, а не база и не полный снимок сайта. Автоматического удаления резервных копий нет.

Перед отправкой проверяется синтаксис PHP и JavaScript. Сценарий не удаляет посторонние файлы и передаёт обновления с отложенной заменой отдельных файлов. Это не атомарное переключение всего сайта: обновляйте в момент минимальной активности учеников. После запуска откройте сайт и проверьте кабинет. При ошибке соединения до передачи повторите запуск после исправления настроек; при частичной передаче можно повторить ту же версию.
